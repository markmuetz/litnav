# Code and architecture review, 2026-11-16 (v0.1.0)

Reviewer: Claude (Opus), with Claude Fable as advisor (a second reading of the
findings and planned fixes, plus a look for what was missed). Scope: all of
`src/litnav`, the web front end, the plugin. Method: read the code along the
paths in `docs/architecture/03-flows.md`, concentrating on the privacy
property (doc 5), the web app's security, long-lived processes (web app, MCP
server), and data loss. Every finding was checked against the code; each fix
has a regression test in `tests/test_review_fixes.py` unless noted.

Severity: **high** = can break the privacy property or lose data;
**medium** = wrong results or resource leaks in normal use; **low** = edge
cases, tidiness.

## Findings and fixes

| id | sev | where | finding | status |
|---|---|---|---|---|
| R1 | high | `commands/core.py` `cmd_share`; `tools.py`; `search.py` | Sharing is stored twice: `meta.toml` (truth) and a copy on index rows. `litnav share KEY confidential` wrote only `meta.toml`, so until the next `litnav index`, `search_literature` (MCP, Ask) kept returning the paper's passages to the model, because search filters on `chunks.sharing`. The same for a hand edit of `meta.toml`. | **fixed**: `share` reindexes the keys at once; `Tools._live()` re-checks every search, paper and list result against the item's current sharing |
| R2 | high (memory) / medium (privacy) | `embed.matrix` | The vector-matrix cache was keyed on `(id(con), model, what, vector count)`. The web app opened a new connection per request, so each semantic search could add a new matrix (~90 MB at 61k passages) and never evict the old ones; `id()` reuse could serve another connection's entry; a sharing change (no new vectors) left the old sharing mask in a long-lived process's cache. | **fixed**: one entry per (index file, model, kind), checked against (inode, `state.gen`, vector count); `index.update` and `embed.update` bump `state.gen` |
| R3 | medium | `index.index_item` | Chunks were written with `vhash = NULL`, filled only by `embed.update`. The web app's tag and sharing writes reindex without embedding, so the paper vanished from semantic search until `litnav index`. | **fixed**: the vector hash is computed when the chunk is indexed (a pure hash; no model needed) |
| R4 | medium | `Library.resolve` | The key and alias maps were cached for the life of the object. In the web app and MCP server, papers imported or renamed from the CLI meanwhile could not be opened (404, "no paper") until a restart. | **fixed**: caches dropped when `papers/` changes (directory mtime) |
| R5 | medium | `web/app.py` `con()`; `Tools.__init__` | The web app opened a read-only SQLite connection per request and never closed it (file-descriptor leak over a long session). `Tools` held one connection for ever, pointing at the deleted file after `index --rebuild`. | **fixed**: `index.Reader`, one shared connection per process, reopened when the index file's inode changes |
| R6 | medium | `ask._claude_code` | If the page closed the stream mid-answer, the `claude` subprocess kept running (using plan quota). The question was passed as an argument, so one starting with `-` would be read as an option. | **fixed**: prompt on stdin; the subprocess is killed when the generator closes |
| R7 | low | `quizzes.path` | `concept:../../x` escaped `quizzes/` (CLI only). | **fixed**: slug validated |
| R8 | low | `index.SCHEMA` | `backlinks` table created but never used (backlinks are computed by scanning notes); the architecture docs described it as filled. | **fixed**: removed from the schema and the docs |
| R9 | low | `tools.reading_due` | Returned recall prompts and reading entries for any key, including confidential ones. | **fixed**: filtered like the other tools (concept cards kept) |
| R10 | low | `tools.related_papers` | `lib.get` on edge keys raised for a key renamed since the last `litnav graph`, failing the whole tool. | **fixed**: stale keys skipped |
| M1 | high (shared hosts) | `web/app.py` | *Found by the advisor.* `GET /` handed the session token and cookie to anyone who could reach 127.0.0.1 with the right Host header. On a shared machine (a JASMIN sci node) another user could read confidential PDFs and sections, change sharing levels, and run Ask on the owner's quota. | **fixed**: a launch key in the printed URL (as Jupyter does); the page and cookie only for holders; cookie named per port |
| M2 | medium/high | `graph.py`, `sources/openalex.py` | *Advisor.* `litnav graph` set `open` whenever OpenAlex reported a CC licence on *any* location (often a repository or preprint copy, not the PDF held), and also over a `private` library default. With `licensed_to_models = false`, that made text sendable on a third-party claim. | **fixed**: publisher's version only; only items at the default `licensed`; source recorded in `files.sharing_source` |
| M3 | medium | `library.py`, `index.signature` | *Advisor.* `library.toml` was read once per process, so changing `licensed_to_models` had no effect on a running web app or MCP server; the index signature omitted the effective level, so a changed `default_sharing` left stale `chunks.sharing` until `--rebuild`. | **fixed**: config reloaded when its files change; level in the signature |
| M4 | medium | `importer.inbox_files`, `Item.add_tag` | *Advisor.* Only the exact folder `_inbox/_confidential/` was special: `_inbox/confidential/` went through Crossref and text extraction as an ordinary tag. Tagging `confidential` (the litman habit) changed nothing. | **fixed**: any spelling of the folder; the `confidential` tag sets the level |
| M5 | low/medium (data) | `rename.apply` | *Advisor.* Notes were read (strict UTF-8) after the item and PDFs had moved; one bad byte left a half-done rename. | **fixed**: notes read and rewritten in memory first; bytes preserved |
| M6 | low | `web/static/app.js` | *Advisor.* Ask answers rendered model-written links; text injected through a PDF could make the model hide note or passage content in a URL behind innocent link text. | **fixed**: links show their full address (no test: front end) |
| R2b, R5b | (refinements) | `index.update`, `embed.matrix` | *Advisor.* Detecting a rebuild by inode is unreliable on Linux (inodes are reused), and rebuilding the 90 MB matrix after every tag click was wasteful; the cache had no lock. | **fixed**: `--rebuild` works in place (no unlink; vectors kept); sharing masks computed per query; generation bumped only when passages change; cache locked. CI confirmed the old behaviour was a real bug on Windows: deleting the index file fails while another process has it open, so `--rebuild` failed whenever the web app or MCP server was running |

## Noted, not fixed

| id | sev | finding | why not now |
|---|---|---|---|
| N1 | low | Web handlers are `async` but do blocking work (search, embedding a query, `index.update`, `git commit`), so one slow request blocks the others. | Single user; fine in practice. Move to sync handlers (Starlette runs them in a thread pool) if it bites. |
| N2 | low | `themes --update` sends the existing `derived/themes.md` back to the model. If a paper was later made confidential, model-written text about its summary is in that file. | The text is a cross-paper synthesis, not the paper's text, and was written while the paper was shareable. A full `litnav themes` regenerates without it. Documented here. |
| N3 | low | Ask history from the page is passed through without checking that roles alternate; a malformed history gives an API error, shown on the page. | Only the owner's own page sends it. |
| N4 | design | CLI writes are not committed to git (the web app's are). | Deliberate: a batch of CLI changes is one commit of the user's choosing. |
| N5 | low | `search.papers` returns `topic` (from the summary) and, under `send_out_strict`, drops licensed papers from paper-level search entirely, although their metadata may be shown elsewhere. | Conservative in the safe direction. |

## Architecture observations

- **One gate, one table** (`sharing.allow`) works well: every outbound path
  checked in this review goes through it. The weak point was the *copy* of
  the sharing level in the index (R1, R2). The rule now: the index copy is
  for speed; anything that reaches a model re-checks `meta.toml`.
- **Long-lived processes** (web app, MCP server) were where caching
  assumptions broke (R2, R4, R5). Caches are now keyed on something that
  changes when the data does (directory mtime, file inode, an index
  generation counter).
- **Files as the truth** held up: no finding needed a change to a file
  format.
- The **CLI layer is thin** and the **web app is mostly read-only**; the few
  write endpoints go through the same library calls as the CLI.

## Advisor (Fable) notes

Fable read the findings and planned fixes against the code. It confirmed
R1-R10 (none wrong), pointed out three weaknesses in the fixes (inode reuse
on Linux, the cost of rebuilding the matrix on every tag change, an unlocked
cache), and found M1-M6. All were fixed. Not fixed:

- hand-added aliases in an existing `meta.toml` are not seen by a running
  web app or MCP server until restart (the `papers/` mtime does not change);
- a disconnected Ask page is noticed only at the next event from `claude`,
  so a silent `claude` lingers until it prints.
